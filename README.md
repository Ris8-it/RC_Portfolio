# RC Portfolio

Personal portfolio of Riccardo Cammarata, financial data engineer. The site shows real work: manual reporting workflows and scanned paperwork rebuilt into SQL models, Python pipelines and dashboards that run without anyone touching them.

**Live site:** https://ris8-it.github.io/RC_Portfolio/

## The idea

Most portfolios describe what someone can do. This one runs it.

Every deploy executes `_pipeline/build_data.py`, which pulls the ECB daily
euro reference rates, reconciles them against the snapshot the previous
build left behind, counts what is new and what was revised, and redraws
the chart and the run log on the front page. A scheduled run does the same
thing on weekday afternoons, so the page refreshes itself whether or not
anyone pushes.

That is the same shape as the pipelines in the case studies: pull,
reconcile, publish, leave a trail. Running one is more convincing than
describing one, and it cannot be faked or prompted into existence.

If the fetch fails, the previous snapshot is kept, the page says
`snapshot stale` instead of `pipeline ok`, and the deploy still succeeds.
Degrade, never break.

## Design

Trading desk. Deep charcoal, one amber accent for what is live and
interactive, green and red reserved strictly for up and down. Monospace
forward, dense, high contrast, flat panels and hairline rules. No
gradients, no glow, no glass, no drop shadows.

Interactions, all of which carry content rather than decorating around it:

1. **Marks on the photograph.** The numbered marks are real footnote
   references. Each reveals a real line about where he is, where he was,
   what he studied.
2. **References on every figure.** Each headline number carries a `[n]`
   that opens its derivation, including what the number does not cover.
3. **The before / after rule** on the case studies, dragged by the reader
   rather than animated at them.
4. **The screenshot viewer**, with a before/after toggle.

Plus a blinking cursor and a status dot, both of which report real state.

Every page renders in full with JavaScript disabled. Nothing is hidden
behind a scroll listener, and the figures are in the HTML rather than
counted up on arrival.

## Structure

```
.
├── _quarto.yml            # site config; excludes templates/ from the render
├── index.qmd              # hero, live panel, figures, case study index
├── about.qmd              # background, toolbox, timeline, how the site is built
├── _live-panel.md         # GENERATED by the pipeline, included by index.qmd
├── _pipeline/
│   └── build_data.py      # the pipeline: fetch, reconcile, chart, log
├── data/
│   ├── snapshot.json      # GENERATED; the observations this build used
│   └── run.json           # GENERATED; what happened during the run
├── projects/              # six case studies
├── styles/theme.scss      # the whole design system, one file
├── assets/
│   ├── site.js            # footnote marks, before/after wipe, lightbox
│   ├── head.html          # fonts
│   ├── status-bar.html    # GENERATED; the strip above the navbar
│   └── after-body.html
├── images/                # screenshots and diagrams
├── templates/             # internal doc skeleton, not published
└── .github/workflows/publish.yml
```

Files and folders beginning with `_` are ignored by Quarto, which is where
the pipeline and the local tooling live. The four GENERATED files are
committed on purpose: the snapshot gives the next run something to
reconcile against, and it puts the data history in git where it can be
audited.

## Run it locally

```bash
python _pipeline/build_data.py    # refresh the data and the panel
quarto preview                    # live reload
quarto render                     # static output into _site/
```

The pipeline uses only the Python standard library.

### Checking it without Quarto

The scripts prefixed with `_` need only Python
(`pip install libsass markdown playwright`) and the Edge that ships with
Windows. No browser download.

```bash
python _build_preview.py      # compile the SCSS and render a static preview
python _shoot.py              # screenshot every page, desktop and mobile
python _test_interactions.py  # assert the interactions still work
python _check_links.py        # every internal link and image resolves
python _check_overflow.py     # no horizontal bleed from 320px to 1920px
python _recolour_svgs.py --from ../portfolio/images   # rebuild the diagrams
```

`_recolour_svgs.py` maps the diagrams from the old theme onto this palette
by role rather than by colour value, strips their animation, and resets the
frames those animations used to start from so nothing is left invisible.
Always run it against the pristine originals, never against already
converted files.

## Publish

A push to `main`, or the weekday schedule, triggers the workflow: run the
pipeline, commit the refreshed snapshot, render, deploy to `gh-pages`.

```bash
git add -A && git commit -m "Update site" && git push origin main
```

One-time setup if Pages is not configured:

- Settings → Pages → Build and deployment → Source: GitHub Actions
- Settings → Actions → General → Workflow permissions → Read and write

## Adding a case study

1. Copy an existing file in `projects/`.
2. Set the front matter: `title`, `description`, `date`, `categories`, `image`.
3. Write it as problem, then what you built, then what changed. Lead with the result.
4. Add a row to the index in `index.qmd`.
5. Any number on the page gets a reference saying where it came from.
